# Гостевой образ: Linux 6.6 для x86-64

Здесь лежит **настоящая 64-битная операционная система**, которую эмулятор
загружает прямо из файла: ядро Linux 6.6 для x86-64 (`x86_64`) вместе с
пользовательским окружением BusyBox, встроенным в образ ядра. Именно её
показывает `?demo=linux`, и её же можно подключить вручную — кнопкой
**Подключить…** напротив «Ядро Linux» или перетащив файл в окно.

| файл | что это |
| --- | --- |
| `linux-6.6-x86_64.bzImage` | ядро Linux 6.6.0 для x86-64 в формате `bzImage` (3030944 байта) со встроенным initramfs (BusyBox 1.36.1 и `beep`, статические сборки) |
| `linux-6.6-x86_64.config` | полный `.config`, с которым собрано это ядро |
| `README.md` | этот файл |

## Что загружается

Ядро загружается **движком** по протоколу загрузки Linux (`bzimage` + параметры
ядра), без BIOS, без загрузочного сектора и без образа диска: файла ядра
достаточно. Параметры по умолчанию — `console=tty0 console=ttyS0,115200`, поэтому
одновременно работают оба консоли:

* **экран** (`tty0`) — текстовый режим VGA 80x25: видно весь журнал загрузки
  ядра, приглашение оболочки, работают эмулируемые клавиатура и мышь
  (нажатие на экран захватывает мышь, как в VirtualBox);
* **COM1** (`ttyS0`) — та же оболочка в панели «Консоль COM1»: команды можно
  отправлять кнопкой «Отправить», а вывод — сохранять в файл.

Внутри — обычный Linux с BusyBox: `sh`, `cat`, `uname`, `free`, `top`, `vi`,
`grep`, `find`, `df`, `dmesg`, `mdev`, `poweroff` и т. д. `/init` — это BusyBox
в режиме `init`, он читает `/etc/inittab` и запускает `/etc/init.d/rcS`, который
монтирует `devtmpfs`, `proc`, `sysfs`, `tmpfs`, печатает баннер и поднимает
оболочки на `ttyS0` и `tty1`.

## Звук

В ядре включён драйвер PC Speaker (`CONFIG_INPUT_PCSPKR`) и интерфейс evdev, а в
образе есть маленькая программа `beep` (`tools/linux-guest/beep.c`):

```
beep            # 880 Гц, 200 мс
beep 440 500    # 440 Гц, 500 мс
```

Она пишет событие `EV_SND`/`SND_TONE` в узел спикера, ядро программирует через
него таймер 8253 и порт 8255 — то самое железо, которое эмулирует движок, — и
эмулятор играет этот тон через Web Audio. То есть звук идёт из настоящей
64-битной системы, а не из тестовой программы.

## Чем это собрано

```
python3 tools/linux-guest/build.py
```

Скрипт скачивает исходники (Linux 6.6 и BusyBox 1.36.1), применяет небольшие
патчи сборочного окружения из `tools/linux-guest/patches.py`, собирает ядро и
initramfs и кладёт готовые файлы сюда, вместе с манифестом. Подробности — в
[tools/linux-guest/README.md](../../tools/linux-guest/README.md).

## Лицензии и происхождение

* **Linux** — GPL-2.0-only, исходники: тег `v6.6` репозитория
  <https://github.com/torvalds/linux> (скачивается как
  `https://codeload.github.com/torvalds/linux/tar.gz/refs/tags/v6.6`).
  Точные изменения сборочного окружения — в `tools/linux-guest/patches.py`, они
  не меняют поведение ядра во время работы: обход отсутствующих в окружении
  сборки `bison`/`flex` (генератор конфигурации заменён на `kconfiglib`) и
  `libelf` (проверки `objtool` отключены). Полный конфиг прилагается.
* **BusyBox** — GPL-2.0-only, тег `1_36_1` репозитория
  <https://github.com/mirror/busybox>, собирается с `CONFIG_STATIC=y`.
* `beep.c` (сборка этого репозитория) — часть образа: собирается
  `gcc -static` и кладётся в `/bin/beep` внутри initramfs.
* Исходники обоих компонентов и скрипты сборки доступны в этом репозитории; это
  и есть предложение исходного кода для бинарного файла выше.

Манифест с контрольной суммой образа лежит рядом (`linux-6.6-x86_64.manifest`),
он создаётся при сборке.
