# Гостевой образ: Linux 6.6 для x86-64

Здесь лежит **настоящая 64-битная операционная система**, которую эмулятор
загружает прямо из файла: ядро Linux 6.6 для x86-64 (`x86_64`) вместе с
пользовательским окружением BusyBox, встроенным в образ ядра. Именно её
показывает `?demo=linux`, и её же можно подключить вручную — кнопкой
**Подключить…** напротив «Ядро Linux» или перетащив файл в окно. Рядом лежит
**загрузочный CD** с тем же ядром (`?demo=cd`): его машина грузит через BIOS,
как настоящий дистрибутивный диск.

| файл | что это |
| --- | --- |
| `linux-6.6-x86_64.bzImage` | ядро Linux 6.6.0 для x86-64 в формате `bzImage` (3625408 байт) со встроенным initramfs (BusyBox 1.36.1 и `beep`, статические сборки) |
| `linux-6.6-x86_64.iso` | загрузочный CD (3678208 байт, ISO9660 + El Torito) с этим же ядром и загрузчиком `linuxboot.S` |
| `linux-6.6-x86_64.config` | полный `.config`, с которым собрано это ядро |
| `linux-6.6-x86_64.manifest` | манифест сборки: версии, параметры, размеры и контрольные суммы |
| `README.md` | этот файл |

## Что загружается

Ядро загружается **движком** по протоколу загрузки Linux (`bzimage` + параметры
ядра), без BIOS, без загрузочного сектора и без образа диска: файла ядра
достаточно. Параметры по умолчанию — `console=tty0 console=ttyS0,115200`, поэтому
одновременно работают оба консоли:

* **экран** (`tty0`) — текстовый режим VGA 80x25: видно весь журнал загрузки
  ядра, приглашение оболочки, работают эмулируемые клавиатура и мышь
  (нажатие на экран захватывает мышь, как в VirtualBox);
* **COM1** (`ttyS0`) — та же оболочка в панели «Консоль COM1»: команды можно
  отправлять кнопкой «Отправить», а вывод — сохранять в файл.

Внутри — обычный Linux с BusyBox: `sh`, `cat`, `uname`, `free`, `top`, `vi`,
`grep`, `find`, `df`, `dmesg`, `mdev`, `poweroff` и т. д. `/init` — это BusyBox
в режиме `init`, он читает `/etc/inittab` и запускает `/etc/init.d/rcS`, который
монтирует `devtmpfs`, `proc`, `sysfs`, `tmpfs`, печатает баннер и поднимает
оболочки на `ttyS0` и `tty1`.

## Звук

В ядре включён драйвер PC Speaker (`CONFIG_INPUT_PCSPKR`) и интерфейс evdev, а в
образе есть маленькая программа `beep` (`tools/linux-guest/beep.c`):

```
beep            # 880 Гц, 200 мс
beep 440 500    # 440 Гц, 500 мс
```

Она пишет событие `EV_SND`/`SND_TONE` в узел спикера, ядро программирует через
него таймер 8253 и порт 8255 — то самое железо, которое эмулирует движок, — и
эмулятор играет этот тон через Web Audio. То есть звук идёт из настоящей
64-битной системы, а не из тестовой программы.

## Диски

К машине можно подключить образы: `.hdd` (жёсткий диск) и ISO (CD-ROM). Движок
показывает их гостю так, как это делает настоящая машина: PCI-функция
`8086:7010` (PIIX3 IDE) с блоками регистров `0x1F0`/`0x3F6` (первый канал),
`0x170`/`0x376` (второй) и блоком bus-master на `0xB400`. Поэтому в ядре
включены `CONFIG_ATA_PIIX` и `CONFIG_ATA_BMDMA` — именно этот драйвер (libata)
и находит диски, а режим обмена гость выбирает сам:

```
ata_piix 0000:00:1e.0: PCI->APIC IRQ transform: INT A -> IRQ 10
ata1: PATA max MWDMA2 cmd 0x1f0 ctl 0x3f6 bmdma 0xc020 irq 14
ata1.00: ATA-0: v86 ATA HD, 1.00, max MWDMA2
sd 0:0:0:0: [sda] 131072 512-byte logical blocks: (67.1 MB/64.0 MiB)
```

Жёсткий диск виден как `/dev/sda` (разделы — `/dev/sda1`), CD — как `/dev/sr0`.
Файловые системы, которые образ может нести: `ext2`, `ext3`, `ext4`, `vfat`
(FAT16/32), `iso9660`, поэтому подходят образы и от Android, и от настольного
Linux, и с флешки.

При загрузке `/etc/init.d/rcS` сам печатает найденные диски и монтирует первую
файловую систему, которая нашлась (сначала раздел, потом диск целиком) — образ
виден изнутри гостя сразу после включения, без команд:

```
Disk:   /dev/sda, 64 MiB
        mounted on /mnt/disk, read-write, contains:
          lost+found proof.txt
CD:     /dev/sr0 mounted on /mnt/cdrom, contains:
          readme.txt
```

Записи гостя идут в копию образа, которая живёт в памяти эмулятора: файл на
устройстве не меняется (это проверяется тестом). Изменённый образ можно
сохранить: приложение складывает записи в оверлей и умеет собрать образ заново
(`BlobBuffer.export_blob`), а снимок состояния содержит образы вместе с
изменениями.

## Загрузочный CD

`linux-6.6-x86_64.iso` — это маленький CD (3.5 МиБ), который загружает то же
ядро **на голой машине**, без единой подсказки от приложения: SeaBIOS читает
запись El Torito, загрузчик в её первом 2048-байтовом блоке
(`tools/linux-guest/linuxboot.S`) находит в ISO файл ядра, читает его через
`INT 13h` и входит в ядро через его собственную точку входа в реальном режиме —
дальше ядро само включает длинный режим, распаковывается и поднимает BusyBox.
Так грузится и любой настоящий дистрибутив, который пользователь подключит к
машине вместо этого CD.

Что внутри ISO:

| файл на CD | что это |
| --- | --- |
| `LINUX.BIN` | ядро, тот же файл `bzImage`, что и рядом в этом каталоге |
| `OPENXISO.IMG` | запись El Torito: загрузчик в первом блоке и ядро сразу за ним |
| `README.TXT` | короткая справка о том, что это за диск (ASCII, чтобы читалось и в гостевой консоли) |

Проверяется это в `linux_test.mjs`: машине не передаётся ни образа ядра, ни
параметров — только CD, — и тест убеждается, что загрузчик напечатал, что
нашёл, что перенёс ровно образ ядра, что ядро получило командную строку от
загрузчика (`ro`) и что гость смонтировал CD, с которого загрузился.

## Чем это собрано

```
python3 tools/linux-guest/build.py      # ядро и initramfs
python3 tools/linux-guest/mkiso.py      # загрузочный CD из этого ядра
python3 tools/linux-guest/mkiso.py --check   # совпадает ли CD в репозитории со сборкой
```

Скрипт скачивает исходники (Linux 6.6 и BusyBox 1.36.1), применяет небольшие
патчи сборочного окружения из `tools/linux-guest/patches.py`, собирает ядро и
initramfs и кладёт готовые файлы сюда, вместе с манифестом. Подробности — в
[tools/linux-guest/README.md](../../tools/linux-guest/README.md).

## Лицензии и происхождение

* **Linux** — GPL-2.0-only, исходники: тег `v6.6` репозитория
  <https://github.com/torvalds/linux> (скачивается как
  `https://codeload.github.com/torvalds/linux/tar.gz/refs/tags/v6.6`).
  Точные изменения сборочного окружения — в `tools/linux-guest/patches.py`, они
  не меняют поведение ядра во время работы: обход отсутствующих в окружении
  сборки `bison`/`flex` (генератор конфигурации заменён на `kconfiglib`) и
  `libelf` (проверки `objtool` отключены). Полный конфиг прилагается.
* **BusyBox** — GPL-2.0-only, тег `1_36_1` репозитория
  <https://github.com/mirror/busybox>, собирается с `CONFIG_STATIC=y`.
* `beep.c` (сборка этого репозитория) — часть образа: собирается
  `gcc -static` и кладётся в `/bin/beep` внутри initramfs.
* `linuxboot.S` (сборка этого репозитория) — загрузчик CD; он и лежит в
  `linux-6.6-x86_64.iso`, рядом со своим исходником (`tools/linux-guest/`).
* Сам ISO — это упаковка ядра и загрузчика, собранная `mkiso.py`; ни одной
  чужой программы в нём нет.
* Исходники обоих компонентов и скрипты сборки доступны в этом репозитории; это
  и есть предложение исходного кода для бинарного файла выше.

Манифест с контрольной суммой образа лежит рядом (`linux-6.6-x86_64.manifest`),
он создаётся при сборке.
